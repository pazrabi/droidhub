# DroidHub Desktop Controller

Автономный первый прототип настольного контроллера DroidHub для **macOS** и **Windows** (также поддерживается Linux с графическим окружением).

Приложение разработано на стандартной библиотеке Python (`tkinter`) и предназначено для локального управления подключенными к компьютеру по USB Android-смартфонами через утилиту `scrcpy`. Не требует изменений существующего сервера DroidHub и работает полностью независимо.

---

## Возможности

- **Обнаружение USB-устройств**: отображение списка подключенных к компьютеру телефонов с актуальным состоянием ADB (`device` / готов к работе, `unauthorized` / требует подтверждения, `offline` / не отвечает).
- **Одновременные живые окна scrcpy**: запуск и закрытие отдельных управляемых окон трансляции экрана и ввода для выбранных локальных USB-телефонов.
- **Вкладка «Экраны USB»** показывает живое видео в тёмной сетке. Поиск по модели или серийному номеру и фильтр готовности обновляют список и сетку одновременно. «Выбрать видимые» отмечает готовые телефоны в текущем списке, «Снять выбор» очищает все отметки. «Открыть выбранные» запускает scrcpy для видимых готовых телефонов с отметками. Двойной клик открывает отдельный телефон. Карточка обновляется снимками, пока открыто окно управления или недоступен видеопоток. При закрытии вкладки захват останавливается.
- **Удалённый сервер DroidHub (GET /api/devices)**:
  - Отдельная вкладка для мониторинга фермы устройств через автономный `HubClient`.
  - Отображение ключевых параметров каждого устройства: имя, онлайн-статус, уровень заряда батареи (с индикатором зарядки), температура и состояние экрана (включен/выключен).
  - Ручной ввод URL сервера (HTTPS) и Bearer-токена авторизации.
  - Поле ввода токена замаскировано символами `*`.
  - **Безопасность токена**: токен хранится строго в оперативной памяти приложения, не записывается на диск, не выводится в консоль/логи и маскируется (`***`) при отображении любых ошибок.
  - **Потокобезопасность Tkinter**: подключение и обновление выполняются в фоновом потоке без заморозки интерфейса; передача данных в GUI осуществляется через потокобезопасную очередь (`queue.Queue`) с опросом в главном UI-потоке.
  - **Защита от устаревших ответов**: результаты запросов, завершившихся после отправки нового запроса или закрытия окна, безопасно игнорируются и не обновляют внутреннее состояние контроллера или интерфейс.
  - **Полная изоляция**: недоступность или сбои удалённого сервера не нарушают работу локального USB-контура; при ошибке подключения отображается понятное сообщение, а таблица устройств хаба очищается, предотвращая ввод пользователя в заблуждение устаревшими данными.
- **Безопасность и стабильность**:
  - Запуск всех внешних процессов строго аргументами списком без `shell=True`.
  - Явный выбор серийного номера (`-s <serial>`) для каждого процесса.
  - Защита от дублирования запусков: нельзя случайно открыть несколько окон scrcpy для одного и того же телефона.
  - Сетевые ADB-устройства (IP:порт) выделяются отдельно и **автоматически не открываются**.
  - Для видео используется служебный процесс scrcpy с фиксированными аргументами через USB. Открытие сетевых ADB-соединений и перенастройка телефона в этот запуск не входят.
  - Запросы к удалённому серверу никогда не отправляются автоматически при старте приложения — только по явному нажатию кнопки пользователем.
  - Корректная обработка отключения USB-кабеля и автоматическое закрытие всех запущенных процессов scrcpy при выходе из приложения.

## Требования

- **Python 3.11+** (включая `tkinter`).
- Внешне установленные утилиты **ADB** (`platform-tools`) и **scrcpy** (программа не выполняет скрытых скачиваний и автоустановок из интернета).
- **Pillow** нужен для миниатюр. Для видео добавьте **PyAV** в то же окружение Python и используйте официальный пакет **scrcpy 5.0.1** с файлом `scrcpy-server` или `scrcpy-server.jar` рядом с исполняемым файлом. [Протокол scrcpy 5.0.1](https://github.com/Genymobile/scrcpy/blob/v5.0.1/doc/develop.md) · [Установка PyAV](https://pyav.basswood.io/docs/stable/overview/installation.html)

```bash
python -m pip install Pillow 'av>=16,<20'
```

### Сборка приложения для Apple Silicon

Откройте готовый `DroidHub.app` двойным кликом в Finder. В сборку входят ADB, scrcpy и зависимости Python. Для самостоятельной сборки используйте Python 3.11+ с Tk под arm64 и распакуйте официальный архив `scrcpy-macos-aarch64-v5.0.1.tar.gz`. [Релиз scrcpy 5.0.1](https://github.com/Genymobile/scrcpy/releases/tag/v5.0.1)

```bash
python -m pip install Pillow 'av>=16,<20' 'pyinstaller>=6.16,<7' certifi
python -m desktop.package_macos \
  --scrcpy-dir /path/to/scrcpy-macos-aarch64-v5.0.1 \
  --dist-dir /tmp/droidhub-dist \
  --work-dir /tmp/droidhub-build
open /tmp/droidhub-dist/DroidHub.app
```

### Сборка и запуск на Windows x64

Распакуйте архив DroidHub целиком и откройте `DroidHub.exe`. Оставьте папку `_internal` рядом с файлом. В сборку входят Python, ADB и scrcpy. Для отдельных моделей Windows может понадобиться USB-драйвер производителя телефона. [Драйверы Android USB](https://developer.android.com/studio/run/oem-usb)

Для самостоятельной сборки используйте 64-битный Python с Tk и распакуйте `scrcpy-win64-v5.0.1.zip`. [Официальный архив и SHA-256](https://github.com/Genymobile/scrcpy/blob/v5.0.1/doc/windows.md)

```powershell
python -m pip install Pillow 'av>=16,<20' 'pyinstaller>=6.16,<7' certifi
python -m desktop.package_windows --scrcpy-dir C:\tools\scrcpy-win64-v5.0.1 --dist-dir .\dist --work-dir .\build
.\dist\DroidHub\DroidHub.exe
```

## 1. Установка ADB и scrcpy

### macOS

#### Способ 1: Homebrew (рекомендуется)
Выполните в терминале:
```bash
brew install android-platform-tools scrcpy
```

#### Способ 2: Ручная установка ADB
Скачайте официальный архив Google SDK Platform-Tools:
[https://developer.android.com/tools/releases/platform-tools](https://developer.android.com/tools/releases/platform-tools)

Распакуйте его так, чтобы исполняемый файл находился по пути:
```
~/android-platform-tools/platform-tools/adb
```
Контроллер DroidHub автоматически проверяет этот путь при запуске на macOS.

---

### Windows

#### Способ 1: Windows Package Manager (winget, рекомендуется)
Откройте PowerShell от имени администратора или командную строку и выполните:
```cmd
winget install Google.PlatformTools
winget install Genymobile.scrcpy
```

#### Способ 2: Chocolatey
```cmd
choco install adb scrcpy
```

#### Способ 3: Ручная загрузка официальных архивов
1. **ADB**: скачайте [Google SDK Platform-Tools for Windows](https://dl.google.com/android/repository/platform-tools-latest-windows.zip). Распакуйте, например, в `C:\platform-tools` и добавьте путь в системную переменную `PATH` (или укажите путь в окне приложения через кнопку «⚙ Пути к утилитам»).
2. **scrcpy**: скачайте официальный zip-архив из репозитория [Genymobile/scrcpy/releases](https://github.com/Genymobile/scrcpy/releases), распакуйте в `C:\scrcpy` и добавьте в `PATH`.

## 2. Настройка Android-телефона (Отладка по USB)

Чтобы телефон появился в списке со статусом **«Готов к работе»**:

1. Откройте на телефоне **Настройки** → **О телефоне** (или **Сведения о ПО**).
2. Найдите строку **Номер сборки** (Build number) и быстро нажмите на неё **7 раз подряд**, пока не появится сообщение «Вы стали разработчиком!».
3. Вернитесь в общее меню: **Настройки** → **Система** (или **Расширенные настройки**) → **Для разработчиков**.
4. Включите пункт **«Отладка по USB»** (USB Debugging).
5. Подключите телефон к компьютеру оригинальным кабелем USB (выберите на телефоне режим подключения «Передача файлов» / MTP, а не только зарядку).
6. Разблокируйте экран телефона. При первом подключении появится системный запрос:
   > *«Разрешить отладку по USB с этого компьютера?»*
   > Поставьте галочку **«Всегда разрешать с этого компьютера»** и нажмите **«Разрешить»**.

> **Важно**: если статус устройства отображается как `Не авторизован`, значит на экране телефона ещё не подтверждён диалог разрешения отладки по USB. Разблокируйте телефон и нажмите «Разрешить».

## 4. Использование интерфейса

В интерфейсе есть вкладки локальных устройств, сервера и привязок.

### Вкладка «📱 Локальные устройства (USB)»
1. **Главная таблица**: отображает список обнаруженных локальных телефонов, их серийные номера, модели, состояние ADB и активность окна scrcpy.
2. **Чекбоксы `[✓]`**: кликайте мышкой по колонке с чекбоксом или нажимайте клавишу `Пробел` для отметки нужных телефонов.
3. **Запуск окон scrcpy**:
   - Кнопка **«▶ Открыть scrcpy для выбранных USB»** запускает независимые нативные окна scrcpy для всех отмеченных USB-устройств в состоянии готовности.
   - **Двойной клик** по строке таблицы мгновенно запускает или останавливает окно scrcpy для этого телефона.
   - Также доступно **контекстное меню** по правому клику мыши.
4. **Закрытие окон**:
   - Кнопка **«⏹ Закрыть все окна scrcpy»** останавливает все запущенные сессии.
   - При закрытии самого приложения DroidHub все дочерние окна scrcpy завершаются автоматически.

### Вкладка «🌐 Удалённый сервер DroidHub»
1. **Подключение к серверу**:
   - Введите HTTPS URL удалённого сервера DroidHub (например, `https://hub.example.com`).
   - Введите Bearer-токен или нажмите **«Вставить»** рядом с полем. Символы маскируются `*`.
   - Нажмите кнопку **«Подключить и обновить»**.
2. **Таблица устройств хаба**:
   - Отображает полученный список устройств фермы: **Имя устройства**, **Онлайн** (🟢 Онлайн / ⚪ Офлайн), **Заряд** (процент и индикатор зарядки), **Температура** и состояние **Экрана** (Включен / Выключен).
   - Запросы к серверу выполняются в фоновом режиме и не блокируют интерфейс.

### Вкладка «Привязки»

После подключения к DroidHub по HTTPS выберите готовый USB-телефон и его запись на сервере, затем нажмите **«Привязать»**. Пара сохраняется на этом компьютере для выбранного сервера. При отключении USB она остаётся в списке, а после подключения обновляется статус телефона. Чтобы изменить пару, удалите существующую привязку и выберите новую.

### Подключение USB-моста

В настольном приложении подключитесь к серверу и сохраните пары на вкладке «Привязки». На вкладке сервера нажмите **«Запустить USB-мост»** и вставьте отдельный токен моста. Пока мост запущен, таблица обновляется каждые три секунды и показывает маршрут управления экраном, который сообщает сервер. Кнопка **«Остановить USB-мост»** закрывает сессию. Токен моста хранится в памяти до остановки.

Задайте на тестовом сервере `HUB_USB_BRIDGE_ID` и отдельный `HUB_USB_BRIDGE_TOKEN`. На компьютере передайте этот токен через `DROIDHUB_USB_BRIDGE_TOKEN` и запустите `python -m desktop.usb_bridge https://hub.example.com`. Укажите тот же URL сервера, для которого сохранили пары во вкладке «Привязки». Каждые три секунды процесс читает локальные привязки и список ADB и отправляет только ID готовых устройств. `Ctrl+C` закрывает сессию. При потере связи отметки исчезают по TTL.

Флаг `--read-battery` разрешает мосту читать заряд через USB. Авторизованный запрос к `GET /api/devices/{device_id}/battery` возвращает заряд, температуру, наличие питания и выбранный транспорт. При отсутствии активного USB-моста сервер читает заряд штатным ADB-подключением.

Флаг `--control-screen` включает USB для запросов скриншота и одиночного нажатия. Если сеанс USB оборвётся после отправки нажатия, сервер вернёт ошибку. Следующий запрос оператора выбирает маршрут заново.

## 5. Ограничения и архитектурные решения первого прототипа

- **Отдельные окна scrcpy** дают ввод с клавиатуры и мыши. Сетка показывает видео разрешением до 288 пикселей по длинной стороне. При отсутствии совместимой сборки, PyAV или при сбое потока сетка использует уменьшенные ADB-снимки.
- **Только USB для scrcpy**: запуск scrcpy предусмотрен исключительно для локальных USB-устройств. Сетевые ADB-устройства (с адресами вида `192.168.x.x:5555`) отображаются в таблице для информации, но автоматически не открываются, во избежание конфликтов и перегрузки каналов.
- **USB-мост** поддерживает чтение заряда, скриншоты и одиночные нажатия по явным привязкам. Для скриншотов и нажатий сервер направляет новые запросы по штатному маршруту Tailscale, когда USB-мост недоступен.
- **Безопасность авторизационных данных**:
  - Токен держится исключительно в оперативной памяти приложения.
  - Токен **не сохраняется на диск**, не пишется в файлы конфигурации, не выводится в консоль или логи.
  - В любых сообщениях об ошибках токен надёжно маскируется.
- **Запросы только по требованию**: при запуске приложения запросы к удалённому серверу без действия пользователя не выполняются.
- **Без перенастройки**: контроллер не меняет системные настройки ADB-сервера, не выполняет `adb tcpip` и не переводит устройства в другие режимы.
