# DroidHub Desktop Controller

Автономный первый прототип настольного контроллера DroidHub для **macOS** и **Windows** (также поддерживается Linux с графическим окружением).

Приложение разработано на стандартной библиотеке Python (`tkinter`) и предназначено для локального управления подключенными к компьютеру по USB Android-смартфонами через утилиту `scrcpy`. Не требует изменений существующего сервера DroidHub и работает полностью независимо.

---

## Возможности

- **Обнаружение USB-устройств**: отображение списка подключенных телефонов с актуальным состоянием ADB (`device` / готов к работе, `unauthorized` / требует подтверждения, `offline` / не отвечает).
- **Одновременные живые окна scrcpy**: запуск и закрытие отдельных управляемых окон трансляции экрана и ввода для выбранных телефонов.
- **Безопасность и стабильность**:
  - Запуск всех внешних процессов строго аргументами списком без `shell=True`.
  - Явный выбор серийного номера (`-s <serial>`) для каждого процесса.
  - Защита от дублирования запусков: нельзя случайно открыть несколько окон scrcpy для одного и того же телефона.
  - Сетевые ADB-устройства (IP:порт) выделяются отдельно и **автоматически не открываются**.
  - Никаких скрытых `adb connect` / `adb tcpip`, перенастроек сервера или телефонов, никакого `adb shell` или root-доступа, никаких внешних сетевых запросов наружу.
  - Неблокирующее обновление: опрос устройств выполняется в фоновом потоке и не замораживает графический интерфейс.
  - Корректная обработка отключения USB-кабеля и автоматическое закрытие всех запущенных процессов scrcpy при выходе из приложения.

---

## Требования

- **Python 3.11+** (включая `tkinter`).
- Внешне установленные утилиты **ADB** (`platform-tools`) и **scrcpy** (программа не выполняет скрытых скачиваний и автоустановок из интернета).

---

## 1. Установка ADB и scrcpy

### macOS

#### Способ 1: Homebrew (рекомендуется)
Выполните в терминале:
```bash
brew install android-platform-tools scrcpy
```

#### Способ 2: Ручная установка ADB
Скачайте официальный архив Google SDK Platform-Tools:
[https://developer.android.com/tools/releases/platform-tools](https://developer.android.com/tools/releases/platform-tools)

Распакуйте его так, чтобы исполняемый файл находился по пути:
```
~/android-platform-tools/platform-tools/adb
```
Контроллер DroidHub автоматически проверяет этот путь при запуске на macOS.

---

### Windows

#### Способ 1: Windows Package Manager (winget, рекомендуется)
Откройте PowerShell от имени администратора или командную строку и выполните:
```cmd
winget install Google.PlatformTools
winget install Genymobile.scrcpy
```

#### Способ 2: Chocolatey
```cmd
choco install adb scrcpy
```

#### Способ 3: Ручная загрузка официальных архивов
1. **ADB**: скачайте [Google SDK Platform-Tools for Windows](https://dl.google.com/android/repository/platform-tools-latest-windows.zip). Распакуйте, например, в `C:\platform-tools` и добавьте путь в системную переменную `PATH` (или укажите путь в окне приложения через кнопку «⚙ Пути к утилитам»).
2. **scrcpy**: скачайте официальный zip-архив из репозитория [Genymobile/scrcpy/releases](https://github.com/Genymobile/scrcpy/releases), распакуйте в `C:\scrcpy` и добавьте в `PATH`.

## 2. Настройка Android-телефона (Отладка по USB)

Чтобы телефон появился в списке со статусом **«Готов к работе»**:

1. Откройте на телефоне **Настройки** → **О телефоне** (или **Сведения о ПО**).
2. Найдите строку **Номер сборки** (Build number) и быстро нажмите на неё **7 раз подряд**, пока не появится сообщение «Вы стали разработчиком!».
3. Вернитесь в общее меню: **Настройки** → **Система** (или **Расширенные настройки**) → **Для разработчиков**.
4. Включите пункт **«Отладка по USB»** (USB Debugging).
5. Подключите телефон к компьютеру оригинальным кабелем USB (выберите на телефоне режим подключения «Передача файлов» / MTP, а не только зарядку).
6. Разблокируйте экран телефона. При первом подключении появится системный запрос:
   > *«Разрешить отладку по USB с этого компьютера?»*
   > Поставьте галочку **«Всегда разрешать с этого компьютера»** и нажмите **«Разрешить»**.

> **Важно**: если статус устройства отображается как `Не авторизован`, значит на экране телефона ещё не подтверждён диалог разрешения отладки по USB. Разблокируйте телефон и нажмите «Разрешить».

## 3. Запуск приложения

Из корня проекта выполните команду:
```bash
python3 -m desktop
```
или:
```bash
python3 desktop/main.py
```

## 4. Использование интерфейса

1. **Главная таблица**: отображает список обнаруженных устройств, их серийные номера, модели, состояние ADB и активность окна scrcpy.
2. **Чекбоксы `[✓]`**: кликайте мышкой по колонке с чекбоксом или нажимайте клавишу `Пробел` для отметки нужных телефонов.
3. **Запуск окон scrcpy**:
   - Кнопка **«▶ Открыть scrcpy для выбранных USB»** запускает независимые нативные окна scrcpy для всех отмеченных USB-устройств в состоянии готовности.
   - **Двойной клик** по строке таблицы мгновенно запускает или останавливает окно scrcpy для этого телефона.
   - Также доступно **контекстное меню** по правому клику мыши.
4. **Закрытие окон**:
   - Кнопка **«⏹ Закрыть все окна scrcpy»** останавливает все запущенные сессии.
   - При закрытии самого приложения DroidHub все дочерние окна scrcpy завершаются автоматически.

---

## 5. Ограничения и архитектурные решения первого прототипа

- **Отдельные окна scrcpy**: каждое устройство открывается в собственном нативном окне операционной системы (SDL2 окно от scrcpy). Это обеспечивает аппаратное ускорение видео, минимальную задержку и полноценную поддержку клавиатуры и мыши. Встроенная мозаичная сетка (embedded grid) в текущей версии намеренно не реализуется.
- **Только USB**: автоматический запуск scrcpy предусмотрен исключительно для USB-устройств. Сетевые ADB-устройства (с адресами вида `192.168.x.x:5555`) отображаются в таблице для информации, но автоматически не открываются, во избежание конфликтов и перегрузки каналов.
- **Без перенастройки**: контроллер не меняет системные настройки ADB-сервера, не выполняет `adb tcpip` и не переводит устройства в другие режимы.
- **Стандартная библиотека**: интерфейс построен на `tkinter` без внешних зависимостей, что обеспечивает мгновенный старт на любой системе с установленным Python.
