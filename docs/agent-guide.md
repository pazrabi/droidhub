# Инструкция для ИИ-агентов по работе с MCP DroidHub

## 1. Устройства в хабе
- **`realme`** (Realme C21Y): менее производительный и более медленный; используйте увеличенные паузы `wait`.
- **`redmi`** (Redmi Note 11): экран 1080×2400 px, работает быстрее.
- **Автопробуждение**: сервер автоматически включает экран и свайпает экран блокировки (`ensure_awake`) при выполнении любого действия; будить телефон вручную не требуется.

## 2. Базовый порядок работы
Работа с устройством всегда строится циклически:
1. **`list_devices`** — получить список доступных телефонов и их `device_id`.
2. **`look`** — получить компактную разметку текущего экрана со списком элементов, номерами `[N]`, типами и координатами центра `(x, y)` в пикселях.
3. **Действие**:
   - **`tap_index`** — нажать элемент по индексу `[N]` из последнего вызова `look` (основной способ взаимодействия).
   - **`type_text`** — ввести текст в активное поле ввода (предварительно активировав поле через `tap_index`).
   - **`swipe`** — выполнить жест свайпа по координатам в пикселях.
4. **`wait`** — выдержать паузу для отклика интерфейса (особенно важно на `realme`).
5. **`look`** — проверить, как изменился экран после действия.

## 3. Скриншоты, ввод текста и координаты
- **Скриншоты (`screenshot`)**: всегда предпочитайте `look` скриншотам — `look` компактен, быстр и экономит токены контекста. Вызывайте `screenshot(device_id, max_width=540)` **только** тогда, когда элементов нет в разметке: в играх, при анализе картинок/графики или содержимого WebView/Canvas. Параметр `max_width` задает ширину JPEG (по умолчанию 540 px).
- **Координаты**: все координаты (`tap`, `swipe`, центры в `look`) указываются в физических пикселях реального экрана.
- **Ввод русского языка и эмодзи (`type_text`)**: латиница отправляется через системный ввод, а кириллица и эмодзи передаются автоматически через ADBKeyBoard (base64 broadcast). Перед вводом обязательно активируйте текстовое поле тапом (`tap_index`).
- **Паузы (`wait`)**: делайте паузы после переходов, запуска приложений и ввода текста для завершения анимаций и сетевых запросов.

## 4. Разрешённые инструменты MCP
Используйте **только** зарегистрированные инструменты DroidHub:
- `list_devices(device_id="")` — список устройств и их статусы.
- `device_status(device_id)` — детальный статус устройства (батарея, температура, экран).
- `look(device_id)` — быстрый текстовый список интерактивных элементов экрана с индексами.
- `tap_index(device_id, index)` — тап по номеру `[N]` из последнего `look`.
- `tap(device_id, x, y)` — тап по координатам в пикселях.
- `tap_element(device_id, text=None, resource_id=None)` — поиск и тап элемента по тексту/ID.
- `swipe(device_id, x1, y1, x2, y2, ms=300)` — свайп между точками в пикселях.
- `type_text(device_id, text)` — ввод латиницы, кириллицы и эмодзи в активное поле.
- `press_key(device_id, key)` — нажатие системной клавиши (`back`, `home`, `recents`, `enter`, `power`, `volume_up`, `volume_down`).
- `open_app(device_id, package)` — запуск приложения по пакету.
- `list_apps(device_id)` — список установленных пакетов.
- `open_url(device_id, url)` — открытие ссылки в браузере.
- `screenshot(device_id, max_width=540)` — скриншот экрана (JPEG).
- `ui_dump(device_id)` — полное дерево UI в XML/JSON (если возможностей `look` недостаточно).
- `wait(device_id, seconds=1.0)` — приостановка выполнения на указанное время.

### Чтение сайтов текстом (Chrome, через DevTools)
Для ботов и парсеров: тапами экран управлять не нужно.
- `fetch_page(device_id, url, wait_seconds=15, capture_json=[], max_chars=200000, wait_for=None, wait_full=False)` — открывает адрес в новой вкладке Chrome, ждёт загрузки и затишья сети (не дольше `wait_seconds`, максимум 60), возвращает `{url, title, text, truncated, captcha, finished, seconds, woke, t_first_match, json_responses: [{url, status, body, t}]}` и закрывает вкладку. `text` — весь `document.body.innerText`, а не видимая часть экрана. `capture_json` — подстроки адресов, ответы которых нужны (например `["/search/v3.2/results"]`); пусто = все JSON-ответы XHR/fetch (до 50, включая трекеры, так что лучше указывать подстроку). `captcha=true` — на странице капча или проверка на робота. `finished=false` — выдача не успела догрузиться за `wait_seconds`, данные частичные. `woke=true` — экран телефона пришлось будить (`ensure_awake`), `false` — экран уже был включен. `json_responses` содержит все подходящие ответы по порядку завершения, по одному на каждый запрос (если сайт опрашивает один адрес несколько раз, придёт несколько ответов); у каждого ответа есть поле `t` (секунды float, округлённые до 2 знаков, от запуска навигации до завершения загрузки `loadingFinished` этого запроса, не убывает). `t_first_match` (число float или null) — наименьшее `t` среди ответов, подходящих под `capture_json` (если `capture_json` пуст — среди любых вернувшихся), либо `null`, если подходящих ответов нет. `wait_for` — подстрока, которая должна появиться в теле одного из ответов (признак конца выдачи, например `"last_update_timestamp":0`); без неё хаб считает страницу готовой, когда подходящие запросы закончились и 1,5 с тишины. `wait_full=true` — ждать `wait_seconds` целиком. HTTP-тело принимает те же поля `wait_for`, `wait_full`.
- `browser_tabs(device_id)` — открытые вкладки Chrome: `index`, `title`, `url`.
- `page_text(device_id, tab_index=0, max_chars=200000)` — полный текст уже открытой вкладки.
- Те же операции по HTTP: `POST /api/devices/{id}/fetch_page` (JSON-тело: `url`, `wait_seconds`, `capture_json`, `max_chars`, `wait_for`, `wait_full`, `replay_post`), `GET /api/devices/{id}/browser/tabs`, `GET /api/devices/{id}/browser/text?tab_index=`; заголовок `Authorization: Bearer <токен>`.
- **Повтор POST с изменённым телом (`replay_post`)**: необязательный параметр `replay_post: {"url_contains": str, "set": dict}` для `POST /api/devices/{id}/fetch_page` и `POST /api/devices/{id}/fetch_jobs`. Когда страница шлёт POST к API сайта (например адрес содержит `/avia/offers/v2`), хаб перехватывает первый POST-запрос, чей URL содержит `url_contains`, парсит его тело как JSON-словарь, делает копию и перезаписывает верхнеуровневые поля значениями из `set`, после чего выполняет из контекста страницы через `Runtime.evaluate` (с `awaitPromise=true`, `returnByValue=true`) вызов `fetch` с сохранёнными заголовками (без служебных `host`, `cookie`, `content-length` и т.п.; `Content-Type` сохраняется, `credentials: 'include'`). Ответ добавляется в `json_responses` ещё одним элементом: `url`, `body`, `t` и `replayed: true`. В `fetch_jobs` ответ попадает в общий поток `responses` (со сквозным номером `i`, отдаётся через `since`/`next`) и учитывается в `t_first_match`, `network_quiet` и `_has_inflight_bodies` (пока повтор в пути, задание не считается тихим или готовым). Повтор выполняется один раз на задание/запрос. Если POST не перехвачен, тело не JSON-словарь, fetch упал или статус не 2xx — повтор молча пропускается с предупреждением в лог (без токенов и тел). Валидация: `url_contains` непустая строка, `set` словарь (иначе 400 Bad Request).
- На один телефон одновременно выполняется один браузерный запрос, остальные ждут в очереди до 90 с (потом 429). Ошибки: телефон недоступен или Chrome не отвечает — 502 с понятным текстом; страница не открылась (нет интернета, DNS) — 502 с кодом ошибки Chrome.
- Только чтение: выполнять произвольный JS нельзя. Вкладка в режиме инкогнито по DevTools не видна. Телефон будится автоматически.

### Фоновые задания загрузки со стримингом ответов (`fetch_jobs`)
Для потокового получения JSON-ответов по мере их загрузки без блокировки клиента:
- `POST /api/devices/{id}/fetch_jobs` — запуск фонового задания. Тело: `url`, `wait_seconds`, `capture_json`, `max_chars`, `wait_for`, `wait_full`, `max_seconds` (float, по умолчанию 45, от 1 до 90 с) и `replay_post`. Сразу возвращает `{"job_id": "..."}`.
- `GET /api/fetch_jobs/{job_id}?since=N` — опрос ответов с номером `i >= since` (длинный опрос до 1 с). Возвращает `{"responses": [{"i": 0, "t": 4.31, "url": "...", "status": 200, "body": "..."}], "next": 1, "state": "running|done|failed", "wait_for_seen": bool, "network_quiet": bool, "elapsed": float, "captcha": bool, "error": str|null}`. Последовательный опрос с `since=next` гарантирует доставку ответов без потерь и дублей.
- `POST /api/fetch_jobs/{job_id}/finish` — чтение страницы и закрытие задания. Возвращает `{url, title, text, truncated, captcha, finished, seconds, woke, t_first_match, json_responses: [{url, status, body, t}]}`. В поле `json_responses` возвращаются только те ответы, которые клиенту ещё не выдавались через GET (если всё выдано, список пуст). Вкладка закрывается, замок снимается. Повторный вызов возвращает 404.
- `DELETE /api/fetch_jobs/{job_id}` — немедленная отмена: закрытие вкладки, снятие замка. Идемпотентен (повторный вызов или неизвестный `job_id` возвращает 200 `{"cancelled": true/false}` без ошибки).

**Правила работы:**
1. **Одно задание на телефон**: на одно устройство в каждый момент времени может выполняться только одно задание; при попытке запустить второе возвращается 429 («занят»). После отмены или завершения телефон освобождается сразу.
2. **Автоотмена через 15 с молчания**: если от клиента нет запросов (GET или finish) в течение 15 секунд, задание автоматически отменяется (вкладка закрывается, замок снимается).
3. **Ошибки и завершение**: если страница не открылась или связь с Chrome оборвалась, `state="failed"`, замок снимается, GET отдаёт описание ошибки в поле `error`, а вызов finish возвращает 502.
4. **Затишье сети и получение тел**: затишье (`network_quiet`) и переход в `done` не наступают, пока тела нужных ответов не получены из Chrome (кроме перехода по `max_seconds`). При вызове `finish` хаб дожидается незавершённых задач тел до 15 секунд.

## 5. СТРОГИЕ ЗАПРЕТЫ
Телефоны являются **реальными физическими устройствами и общими для пользователей**.
Категорически запрещено:
1. Входить в важные и личные аккаунты (банки, Госуслуги, соцсети, почту) и вводить пароли/секретные данные.
2. Совершать финансовые операции, платежи, переводы и подписки.
3. Отправлять SMS, сообщения в мессенджерах, письма или совершать звонки от имени владельца.
4. Удалять любые данные: файлы, фотографии, приложения, чаты, историю или настройки.
5. Изменять настройки безопасности, блокировки экрана, аккаунтов, сети (Wi-Fi, VPN, Tailscale) или режим разработчика.
6. Устанавливать сторонние приложения (через APK или магазины приложений).

## 6. Поведение при ошибках
- **Устройство оффлайн**: проверьте статус через `device_status` или `list_devices`. Если телефон недоступен, прекратите попытки действий и сообщите пользователю о потере связи.
- **Ошибка 429 (Превышен лимит действий)**: сработал ограничитель частоты запросов. Подождите через `wait` и снизьте частоту вызовов.
- **В `look` нет элементов (`(нет значимых элементов)`)**: подождите (`wait`) загрузки интерфейса и повторите `look`. Если на экране игра, графический контент или неразмечаемый WebView — сделайте `screenshot`.
- **Устаревание кэша `tap_index`**: кэш индексов `look` действует 120 секунд; если он устарел, вызовите `look` повторно перед тапом.

## 7. Завершение сессии
После выполнения всех задач **обязательно** верните устройство на домашний экран:
`press_key(device_id, key="home")`.
